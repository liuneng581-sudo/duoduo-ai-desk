# 多多AI客服 功能盘点（基线版本 1.0.3）

> 盘点日期 2026-07-03。用途:为 1.0.4 版本规划提供功能基线。
> 说明:原始 TS 源码大部分丢失,盘点基于编译后可读 JS(后端 dist / companion index.js / 主进程)+ 前端压缩 bundle 字符串反推 + prisma schema。

---

## 一、产品架构

单体 Electron 桌面应用,client + server + companion 全打进一个 app,跑在商家本机。

- **client(前端)**:React + AntD5 SPA,单窗口 1280×860,最小化到托盘,从 `localhost:3001` 加载,axios 打本机 Express。
- **server(后端)**:本地 Express `127.0.0.1:3001` + SQLite(prisma)。所有数据挂单一 owner 账号(一机一码授权模式)。
- **companion**:Playwright 驱动**内嵌 WebContentsView** 里的拼多多商家后台(`mms.pinduoduo.com`),每店独立会话,通过 WS(`/ws`,token+AES 加密)与 server 通信。所有 PDD 数据靠在登录页内跑同源 fetch(PDD 自己的 JS 负责签 anti_content)。
- **license-server**:独立云端服务,部署 `pdd.fxisv.com`,授权签发 + 下载站 + 兑换页。

## 三、后端功能模块(12 块)

### 1. 账号与认证
注册/登录/登出/刷新/获取用户/改资料。双 token(access + httpOnly refresh cookie 7天)。登出 bump token version。防爆破限流。授权模式下有隐藏 owner 账号(`owner@local`)。

### 2. 店铺管理
店铺 CRUD;登录凭据 AES 加密存储(只返回 hasLoginCredentials 布尔,不回显);每店 AI 开关(aiEnabled/aiPauseOnSensitive);店铺状态 active/paused/closed;浏览器状态 idle/connecting/online/error/needs_login/needs_captcha。

### 3. 商品知识库(单店)
- 字段:名称、价格、库存、分类、商品链接、描述、图片URLs、上架状态。从链接解析 goods_id 去重。
- **Excel 批量导入/导出/模板**(≤5MB ≤5000行,中英表头映射,逐行报错)。
- **一键从PDD同步全量商品**(异步任务+进度轮询)。

### 4. QA 问答库(单店)
问题/答案/关键词/分类/启用开关。Excel 批量导入/导出/模板。用于政策服务类标准答复。

### 5. AI 对话/自动回复(核心)
- **上下文**:场景自动识别(售前/售中/售后)、最近30条历史、店铺信息、在售商品(≤50)、QA库(≤100)、重点商品聚焦(按goods_id匹配)、售后订单退款状态注入。
- **人设话术**:拟人真人客服、禁Markdown/emoji、回复简短、禁露AI身份;只用真实商品数据答价格库存规格;政策照QA库;改地址→"已向物流报备"安抚+飞书;后台处理(改备注/催发货/改价合单/开票)→"已通知同事后台处理"安抚+飞书。
- **6类转人工**:①AI关闭 ②敌对场景(投诉/差评/纠纷/曝光/工商/起诉…,可开关;普通退款退货不再转) ③单会话24h回复超上限(默认50) ④合规红线拦截 ⑤空回复兜底话术 ⑥LLM/DB异常兜底。
- **3类合规硬扫描**(发送前):站外引流、负面态度话术、极限词/虚假承诺。运费险/七天无理由等售前权益名先剥离防误判。
- 幂等去重(按PDD msg_id)、回复清洗、售后场景自动结单。
- **人工接管**:查看会话、手动回复(过合规检查)。

### 6. 数据看板/统计
总览(所有店铺卡片)、单店摘要、单店实时营收(companion 实时拉PDD)。上海时区。

### 7. 图片处理
文生图/图生图(OpenAI 兼容)、5档尺寸、质量、张数1-4、历史分页/删除、SSRF防护。

### 8. 授权 License
一机一码 Ed25519 离线验签、永久(days=0)/限期(trial带剩余天数)、换机失效、防拷贝防篡改。

### 9. 全局/门店配置
- **全局(按店主)**:API Keys、AI Providers(多provider CRUD+测试,加密脱敏)、飞书Webhook、默认provider/图片参数、Agent默认行为配置。
- **单店**:AI开关、敌对转人工开关、登录凭据、Agent行为配置覆盖(agent_config_{storeId})。
- Agent配置加载:单店→回退店主默认→内置默认,1分钟缓存。

### 10. Companion 网关(WS /ws)
token鉴权+Origin拦截;按storeId路由;30s心跳检测假在线;告警聚合(needs_login/captcha/error/pending_human)供前端铃铛;凭证WS加密下发。前端店铺浏览器控制REST(连接/断开/状态)。

### 11. 飞书通知
需登录/需验证/系统异常/需人工/每日摘要/测试。卡片或纯文本。best-effort不阻断。30s冷却去重。

### 12. 其他
健康检查、JWT/店铺归属校验/zod校验/限流中间件、AES-256加密、URL安全校验。`Customer`/`Order`/`OrderItem` 模型已定义但无专门REST端点,由AI上下文和看板消费。

## 四、Companion 能力(实测活代码)

> `server/dist/services/pdd/*.js`(sessionPool/wsInterceptor/browserManager)是**旧方案死代码**,已被 `companion/index.js` + `gateway.js` 取代。

### 消息收发(已实现)
- **收**:纯HTTP轮询,每5秒一轮,每店一loop。`POST /plateau/chat/latest_conversations`(size50)取user新消息,msgId去重;每条新消息拉最近20条上下文取10条文本。抓商品期间暂停轮询防风控。风控40002上报error。二进制Titan WS不解析。
- **发**:`send_reply`→页面内`POST /plateau/chat/send_message`(anti_content留空)。发送前sanitize剥think块/Markdown。

### 数据抓取(已实现)
| 能力 | 协议 | 接口 |
|------|------|------|
| 全量商品目录 | fetch_all_goods→all_goods(+goods_progress进度) | `POST /vodka/v2/mms/query/display/mall/goodsList`(page,size100,翻页到total,上限500页/5万条) |
| 店铺统计 | fetch_store_stats→store_stats | 营收概览+订单状态统计 |
| 客户消息 | 主动推 customer_message | 5s轮询 |

**签名复用机制**:无法自造anti-content,导航到商品管理页拦截页面自己的请求偷签名复用翻页;~11页后签名失效自动重新导航刷新重试,去重按externalId绝不跳过("可以慢但必须准")。

### 商品字段
- **抓到**:externalId(goods_id)、name、price(sku_group_price[0]或market_price,分转元)、stock(quantity)、category(cat_name)、description(goods_desc+SKU汇总"规格:黑色XL ¥xx 库存xx")、isOnsale、SKU明细(前60条拼进description)。
- **没抓**(⚠️产品规划重点):**运费/包邮规则、发货时效(body带shipment_time_type:3但结果没解析)、材质/成分、结构化规格键值(只有拼好的字符串)、商品图片/详情图文、销量评价、预售信息(带pre_sale_type:4但没取)、创建/上架时间**。
- 商品URL是server端用externalId拼的,非抓取所得。

### 订单上下文(orderHint,已实现)
每条customer_message附:hasOrder、orderSns(订单号数组)、goodsIds(客户贴的商品ID)、afterSales(售后状态如"未发货退款成功")。**没有**订单金额/商品明细/收货/物流。

### 登录/会话
Playwright持久化context(每店独立profile+cookie 0600);账密自动登录(检测login页填表);验证码→上报needs_captcha+飞书,最长等300s;多店独立session Map;两种模式(嵌入式attach Electron / 独立式launch后台Chromium)。

### 稳定性
浏览器崩溃自愈(2s重启最多5次,用尽后5分钟长延迟);白屏自愈(evaluate超时判渲染器挂死→恢复);双向30s心跳防假在线;进程级unhandledRejection不崩;poll mutex防重入;软硬限流分级退避。

## 五、license-server 能力

### 授权类型(仅3种)
| 类型 | days | 端点 | 鉴权 |
|------|------|------|------|
| 试用 | 7 | `POST /api/license/trial {machineId}` | 无(去重表) |
| 一年 | 365 | `POST /api/license/issue {machineId,plan:year,adminEmail,adminPassword}` | 超管 |
| 永久 | 0 | `POST /api/license/issue {...plan:permanent}` | 超管 |

**没有独立"买断"类型,permanent(永久)即买断。**

### 机制
- Ed25519签名`${machineId}:${days}`→追加2字节days→base32编码分组=激活码。绑machineId,换机失效,客户端离线验签。
- 私钥`license-private.key`只在服务器,不存则exit(1)。
- **无预生成码池/卡密**,所有码按提交的machineId实时签发。
- **无支付/订单闭环**,正式授权全靠超管手动签发,不可自助购买。

### 试用去重
`trial_claims`表(PK=machineId),已领返409+原码。**弱点**:machineId客户端本地生成,删文件/改MAC可绕过重领。

### 超管
`safeEqual`防时序比对ADMIN_EMAIL/PASSWORD(环境变量,**默认明文硬编码admin@openclaw.com/admin123**)。签发流水写issued_licenses表(操作者/IP,可审计)。🔴生产未覆盖环境变量则任何人可从兑换页签发永久授权。

### 静态页
`index.html`(下载页,Win/Mac下载+引导)、`redeem.html`(兑换页,试用+超管签发双Tab)。`/downloads/`运行期投放安装包+latest.json+latest.yml/latest-mac.yml(electron-updater更新源),不入git。

### 存储
SQLite:`trial_claims`(试用去重)、`issued_licenses`(签发流水)。存码明文,不存到期时间(days编入码,客户端离线判)。

### 部署
监听127.0.0.1:4010,nginx反代。环境变量可覆盖PORT/BIND_HOST/私钥/DB/超管凭据。

## 六、数据模型(prisma)

User、Store、Product、QAEntry、Conversation、Message、Customer、Order、OrderItem、ApiKey、ImageGeneration、SystemConfig。

**Product 无结构化运费/材质/规格/发货字段**(只有自由文本 description≤2000字)——这是"运费/材质 AI 答不了"的数据根因。

## 七、给 1.0.4 的关键结论

1. **"一键抓取商品"已存在**,但抓的字段不含运费/材质/规格/发货。客户抱怨的正是这些没抓到。
2. **运费/材质 AI 答不了 = 三重原因叠加**:①companion 没解析这些字段 ②Product 表没有这些列 ③prompt 指令"知识库没有就说'我帮您确认下'"。
3. **批量其实已支持**(Excel 导入导出)——客户说"不支持批量"可能是没找到入口 = 引导/体验问题。
4. **计费(点数)逻辑不在这套代码里**——点数扣费应在 API 中转/网关侧(zaneai.net / minimax),本项目只是消费方。计费透明度问题需在中转侧或界面说明解决。
5. **前端改动成本高**(源码丢失),涉及界面的需求要评估重建源码。
