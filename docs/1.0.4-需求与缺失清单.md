## 一、Bug(客户已报,必须修)

### B1 🔴 批量导入导出全线不能用【根因已确认】【后端】
- **现象**:商品库、QA库的 Excel 导入/导出/下载模板,客户全都用不了。
- **根因(运行时验证,非猜测)**:blob 下载被 App 安全策略拦死。前端导出/模板走 `createObjectURL`→`<a download>` 生成 `blob:` URL,但 main.js:710 的 will-navigate 白名单只放行 `http://localhost` 和 `data:`,没放行 `blob:` → preventDefault 拦截;main.js:778 的 CSP 也无 `blob:` 再挡一层。两层叠加 → 全灭。
- **已排除**:exceljs/multer 确实打进包(实测能跑)、路由确实注册、响应头正确、打包产物与源一致。**功能本身没坏,是下载通道被掐。**
- **修复**:main.js 的 will-navigate 白名单 + CSP 放行 `blob:`,或注册 will-download 走保存对话框。**纯改 dist-electron/main.js 可读JS,0.5天,不卡前端源码。**
- **导入侧低置信疑点**:前端写死 multipart Content-Type 缺 boundary(在压缩bundle里),但 axios 大概率自动纠正。先修导出验证,再看导入是否仍坏。

### B2 🔴 睡眠/黑屏掉线回归【根因已确认】【后端】
- **现象**:电脑一黑屏/休眠就掉线。客户明确:以前版本睡眠也后台跑,两三天才掉一次。
- **根因**:1.0.3 (commit a363ae1)"白屏根治"新加了内存监控软重启(main.js:351,连续2次超硬阈值→app.relaunch())+ 店铺视图3h周期reload。**全程无 powerSaveBlocker/powerMonitor**。睡眠唤醒后 getAppMetrics 内存读数失真 → 误判超阈值 → 重启整个app → companion全掉 = 掉线。旧版没这套所以睡眠不掉。
- **修复**:加 powerMonitor 监听 suspend/resume,睡眠暂停监控、唤醒缓冲后恢复;内存relaunch加唤醒护栏。**纯改 main.js,不卡前端源码。**
- **优先级**:最高。影响核心可用性 + 是回归 + 修复干净。

### B3 🟡 AI"该插嘴的还是会插嘴"【后端】
- **现象**(客户反馈):AI 在不该回复的时候仍然回复。
- **落点**:aiChat.service.js 的回复边界/转人工判断逻辑。需要客户给具体例子(什么场景不该回却回了)才能精准修。
- **备注**:需补充复现场景。

## 二、新功能(客户明确要求)

### F1 🟢 飞书群引导(商家进群求助)【前端】
- 商家用软件遇到问题时,软件内有入口引导他加入你的售后飞书群。
- 落点:前端加入口(右上角/帮助区),配一个群二维码或链接。轻量,但要改界面。

### F2 🟢 信息通知,两部分【前端+后端】
- **F2a 修好现有告警**:通知中心铃铛现在"不准/不刷新/是假的"。要真实反映状态并实时刷新。落点:前端铃铛组件 + 后端 /pdd/alerts 数据准确性。
- **F2b 新增软件内公告/远程推送**:你能远程下发通知给所有客户(新版本/维护/活动),客户在软件里看到。**这是新能力**:需 license-server 或新服务加公告下发接口 + 客户端拉取展示。【后端新接口 + 前端展示】

### F3 🟢 全面补时间提示【主要前端】
- 显示:授权激活时间、到期时间、剩余天数;会话/消息时间;商品最后同步时间;店铺最后连接时间等。
- **核查结论**:数据库时间字段大多已存(全表createdAt/updatedAt、订单paidAt/shippedAt/deliveredAt、店铺cookieExpiresAt),授权到期可从激活码days算。**所以主要是前端没显示,不是没数据。** 少数需新增字段(如Product.lastSyncedAt、Store.lastConnectedAt)。

### F4 🟢 右上角使用教程引导【前端】
- 形态:图文帮助中心 + 首次使用分步引导 都要。
- 解决客户搞不懂"全局配置/门店问答库/商品知识库"的痛点(对话里反复要远程教)。
- 落点:纯前端。图文内容需你我共同产出。

## 三、功能缺失 / 逻辑不全(盘点发现,客户暗示或未明说)

### M1 ⚪ 运费/材质/规格 AI 答不了(客户反馈里最核心的痛点)【后端+可选抓取层】
- **三重缺失叠加**:①companion 抓商品时没解析运费/材质/规格/发货(body带shipment_time_type/pre_sale_type但结果没取)②Product表无这些结构化字段,只有自由文本description ③prompt规定"知识库没有就说'我帮您确认下'"。
- **补全方案(分层)**:
  - 快:加"店铺级物流政策"字段(全店包邮/48h发货),注入prompt。运费通常全店统一,不用逐商品。【后端】
  - 中:Product加运费/材质/规格/发货结构化字段 + Excel导入模板加列 + prompt拼进去。【后端,连带schema迁移】
  - 深:companion抓这些字段。【抓取层,改companion index.js】

### M2 ⚪ 抓取字段单薄(盘点)【抓取层】
- 现在抓商品只有 id/名称/价格/库存/分类/描述/SKU。**没抓:图片、运费、发货时效、材质、结构化规格、销量、预售、上架时间。**
- 是 M1 的根因之一,也是独立的能力短板。

### M3 ⚪ "批量不支持"其实是认知问题(客户反馈)【前端引导】
- 客户说"暂时不支持批量",但盘点显示 Excel 导入导出**已实现**。→ 是没找到入口/不会用。F4教程 + F1引导可覆盖。(注:但 B1 说明现在导入导出还坏着,得先修好 B1。)

### M4 ⚪ 计费点数不透明(客户反复询问)【说明/中转侧】
- 客户问"点数按回复量还是店铺数扣"。**扣费逻辑不在本项目**,在API中转侧(zaneai.net/minimax)。本项目是消费方。
- 补全方向:界面加计费口径说明 + 用量展示(若中转侧有接口可拉)。需你确认中转侧能否提供用量数据。

### M5 ⚪ 授权无自助购买/续费闭环(盘点)【license-server】
- 现在正式授权全靠超管手动签发,无支付、无码池/卡密。客户"买了软件还要充钱"的困惑部分源于此。
- 是否要做自助购买/发卡,取决于你的商业模式,非必须。

### M6 ⚪ license-server 安全隐患(盘点)【后端】
- 超管邮箱和密码只从环境变量读取。未设置，或密码过弱 / 为已知默认口令时，服务拒绝启动。源码中不再保留默认口令。
- 私钥仍只放在服务器上，不入库。
